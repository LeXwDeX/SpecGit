SpecGit

SpecGit gives coding agents a shared delivery workflow for GitHub and GitLab. Issues hold the specification. A native PR or MR gathers the selected Issues and the implementation. SpecGit reads the forge's current state so the agent can repair failures and distinguish pending work from completed delivery.

Install

Open your coding agent in the repository you want to use with SpecGit and ask it to read and follow the agent installation guide. The guide downloads the latest stable signed GitHub Release, verifies its signature and SHA-256, installs the shared CLI, and initializes the project.

One user-level executable serves every repository and worktree. End-user installation needs no Node.js, npm or Rust compiler; repository work needs Git and an authenticated gh or glab. GitHub Releases is the only distribution channel.

After installation, initialize each clone or worktree separately and inspect the offline capability catalog:

specgit init --provider github --remote origin --check --json
specgit init --provider github --remote origin --dry-run --json
specgit init --provider github --remote origin --json
specgit setup --catalog --json

Already installed? Use the project maintenance guide instead of repeating the first-install procedure.

Host quick start

SpecGit capability lives in the shared CLI and the native Git guard, so a project works with zero host integration. Naming a host with --agent adds its guidance and Skill only; hooks and managed read-only permissions are separate explicit choices. Preview with --dry-run, then repeat the command without it to apply.

Generic

Guidance entry in AGENTS.md and the canonical .agents/skills/specgit-native/SKILL.md. No host callbacks; the native Git guard still applies on commit and push.

specgit setup --agent generic --dry-run --json
specgit setup --agent generic --json

Fallback: read the guidance and Skill directly. Details: Supported Hosts.

Claude Code

Root CLAUDE.md entry, the canonical .agents Skill, and a .claude/skills/specgit-native/SKILL.md copy. Context hooks and the managed read-only allowlist are optional.

specgit setup --agent claude --dry-run --json
specgit setup --agent claude --json
specgit setup --agent claude --hook-purpose context --dry-run --json
specgit setup --agent claude --hook-purpose context --json
specgit setup --agent claude --readonly-permissions --dry-run --json
specgit setup --agent claude --readonly-permissions --json

The allowlist reduces prompts; it is not a sandbox or an authorization boundary. Details: Supported Hosts.

Codex

Canonical .agents Skill and a guidance entry in AGENTS.md, or in an existing nonempty AGENTS.override.md. Context hooks go to .codex/hooks.json.

specgit setup --agent codex --hook-purpose context --dry-run --json
specgit setup --agent codex --hook-purpose context --json

Trust the project .codex/ layer in the host's /hooks review; registration is reported as written_not_verified until the host imports it. Details: Supported Hosts.

OpenCode

The official build receives the root AGENTS.md entry and the .agents Skill; context hooks are declined. A custom fork supporting Claude-compatible command hooks can opt in explicitly.

specgit setup --agent opencode --dry-run --json
specgit setup --agent opencode --json
# Custom fork only:
specgit setup --agent opencode --opencode-claude-hooks --hook-purpose context --dry-run --json
specgit setup --agent opencode --opencode-claude-hooks --hook-purpose context --json

Fallback: re-read the guidance and Skill and use bounded watch/inbox; the Git guard remains independent. Details: Supported Hosts.

Download

SpecGit is distributed only through GitHub Releases. The latest stable release provides:

  • specgit-<version>-darwin-arm64.zip — macOS arm64
  • specgit-<version>-linux-x64-gnu.zip — Linux x64 glibc
  • specgit-<version>-win32-x64.zip — Windows x64
  • SHA256SUMS and SHA256SUMS.sigstore.json — checksum manifest and its Sigstore signature bundle

Verify the signature and SHA-256 with the release asset verification reference. The signature covers SHA256SUMS and therefore the ZIP bytes; cross-check the tag commit and the native build workflow run separately.
