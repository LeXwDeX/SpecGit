规格 · 实现 · 验证 · 交付

从 Issue 规格到验证交付。

SpecGit 为编码 agent 提供 GitHub 与 GitLab 共享的交付工作流。规格写在 Issue，原生 PR/MR 汇聚所选 Issue 与实现，SpecGit 读取平台实时状态，让 agent 能修复失败、区分待办与已完成的交付。

交付管道

一个 Issue，一条可追溯的上线路径。

每个提交通过本地 checkpoint 绑定所选 Issue。SpecGit 汇聚原生 PR/MR 并观察平台，交付以实时状态验证——绝不靠假设。

01

Issue 规格 spec

Issue 承载 原因 / 范围 / 方案 / 验收。specgit issue --inspect 在创建前对 WHY 查重。

02

本地 checkpoint bind

checkpoint 在分支上记录所选 Issue。原生 Git guard 在每次 commit/push 检查它与 Issue: #N trailer。

03

原生 PR / MR build

agent 实施后由 specgit pr 把所选 Issue 汇聚为一个原生请求，保留关闭引用与 PR 模板。

04

CI 与评审 observe

specgit watch 与 pr --status 读取当前 head 的检查与评审。失败在范围内修复，绝不弱化保护。

05

合并 ship

必需检查通过且 head 干净时在平台合并。SpecGit 回读合并结果——退出码 0 本身从不等于完成。

06

验证关闭 verify

仅当目标分支已合并、每个关联 Issue 以原生证据关闭时才确认交付——不靠本地猜测。

07

签名发布 release

独立的签名 GitHub Release 发布三平台 ZIP 与 Cosign 签名的 SHA256SUMS。合并不等于发布。

产品原则

生而宿主中立。

能力首先在 CLI 与原生 Git guard 中实现。宿主只增加提示与上下文——绝不承载业务规则。

零宿主可用

项目无需任何宿主集成即可工作。共享 CLI 与 Git guard 独立交付完整工作流。

原生 Git guard

pre-commit/pre-push 检查把每个提交绑定到所选 Issue。不用 --no-verify，不弱化保护。

实时状态验证

SpecGit 读取平台当前状态，区分待办与已完成交付，并在范围内修复失败。

受管宿主资产

宿主指导、hooks 与只读白名单都是显式、受管、可刷新、可移除的——绝不写全局状态。

安装

一个可执行文件，服务所有仓库。

在仓库中打开你的编码 agent，让它遵循 agent 安装指南：下载最新签名 GitHub Release，校验签名与 SHA-256，安装共享 CLI 并初始化项目。无需 Node.js、npm 或 Rust 编译器。

specgit init --provider github --remote origin --check --json
specgit init --provider github --remote origin --dry-run --json
specgit init --provider github --remote origin --json
specgit setup --catalog --json

已安装？请使用项目维护指南。原生 specgit CLI 仅通过 GitHub Releases 分发。

宿主快速上手

带上你自己的 agent。

用 --agent 指定宿主只增加其指导与 Skill；hooks 与受管只读权限是独立的显式选择。先用 --dry-run 预览，再去掉它重复执行以应用。

Generic

指导写在 AGENTS.md 与规范的 .agents/skills/specgit-native/SKILL.md。无宿主回调；Git guard 仍生效。

specgit setup --agent generic --dry-run --json
specgit setup --agent generic --json

回退：直接阅读指导与 Skill。Supported Hosts。

Claude Code

根 CLAUDE.md、规范 .agents Skill 加 .claude/skills 副本。上下文 hooks 与受管只读白名单可选。

specgit setup --agent claude --dry-run --json
specgit setup --agent claude --json
specgit setup --agent claude --readonly-permissions --json

白名单减少提示，不是沙箱。Supported Hosts。

Codex

规范 .agents Skill，指导写在 AGENTS.md 或已存在的非空 AGENTS.override.md。上下文 hooks 写入 .codex/hooks.json。

specgit setup --agent codex --hook-purpose context --dry-run --json
specgit setup --agent codex --hook-purpose context --json

在宿主 /hooks 复核中信任 .codex/ 层。Supported Hosts。

OpenCode

官方构建获得 AGENTS.md 入口与 .agents Skill；上下文 hooks 被拒绝。自定义 fork 可显式选用 Claude 兼容 hooks。

specgit setup --agent opencode --dry-run --json
specgit setup --agent opencode --json

回退：重读指导并用有界 watch/inbox。Supported Hosts。

安装前先校验

每个发布附带 SHA256SUMS 与 SHA256SUMS.sigstore.json。Cosign 签名覆盖 SHA256SUMS 从而覆盖 ZIP 字节；请另行交叉核对 tag 提交与原生构建工作流运行。见发布资产校验参考。
