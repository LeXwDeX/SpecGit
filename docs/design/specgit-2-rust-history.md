实现任务对保留/调整项给出具体回归或真实运行证据；对交回平台/Agent 项给出责任归属与观察场景，证明核心不接管该动作；对退役项给出当前执行链与已安装资产的清点。历史项记录来源即可，不重做旧发行。不要写一批只断言“表格含某句”的产品测试。

同一个修复在旧版本已关闭，不代表在 Rust 中自动通过；后续 Issue 仍打开，也不代表其候选代码完全不存在。当前分支、代码与证据状态见交接文档，最终在实际实施 SHA 上核对。对发现的新根因使用已有同 WHY Issue，确有新 WHY 才新增。

对 #476/#511/F30 的重点修订：本次允许的是 **hook 通知后的可选 Agent 补关**。服务端仍负责正常自动关闭；SpecGit 核心和 hook 不执行关闭。这条修订覆盖旧“任何人工补关都不允许”的表述，不恢复旧独立关闭控制器。

对 #535/#536 的重点修订：类型化观察、输出分离和 adapter 协议隔离继续成立；不再要求实现纯 acceptance、merge 消费方或 promotion 协议。后续任务先更新这些现有 Issue 的生效范围，再按新范围开发。

对 #514/F44 的重点修订：自有 runner 与当前 npm trusted publishing 能力存在不兼容；按 [主设计 §7.3](specgit-2-rust-design.md#73-分发与发布边界) 处理，不用未经验证的 OIDC 承诺推进发布。
