## Evaluation and failure patterns

The September 15 delivery discussed by the user reached a local commit and test
deployment but stopped before push/PR and live model acceptance. The execution
reviewer rejected a combined commit/push, then a standalone push after repository
ownership verification, and separately rejected production credential reuse.
The user subsequently authorized the destination and credential use; work resumed.

- P1: bundled local and external effects obscure individual action scope.
- P2: general delivery authorization and repository facts were insufficient for
  this reviewer's destination decision; skill text cannot guarantee acceptance.
- P3: test deployment and cross-environment credential use are distinct scopes.

## chg-1: explicit approval context in the delivery skill

- Evidence: the failures above and the user's request to refine actions.
- Cause: existing guidance preserved authorization boundaries but omitted the
  context needed at each execution request and recovery after host rejection.
- Repair: separate effects before execution, state authorization/target/change
  scope/evidence, retain credential boundaries and explicit rejection handling.
- Prediction: future requests expose their individual effects and existing
  authorization; unrelated authorized work continues if one action is blocked.
- Risk: extra calls add overhead; evidence may still be rejected. Splitting a
  rejected action to evade review remains prohibited.
- Layer: skill workflow guidance, with this report as evaluation evidence.
