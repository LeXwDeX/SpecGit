# AHE prompt revision — SpecGit 2.0.1

## Scope and component map

Project guidance is rendered by `guidance.rs`; host entry blocks by `setup.rs`;
the installed workflow skill comes from `runtime/assets/SKILL.md`. Hook context
in `hook.rs` supplies current local identity and pending native observations.
The audit covers English/Chinese project text, Codex/OpenCode host entries,
Claude hook text, the installed skill, initial injection, refresh and migration.

## Evaluation notes

Native ownership and authorization boundaries were already explicit. The
workflow sequence and completion semantics were under-specified, and local
exclusion was missing as an executable mechanism. Template bodies are omitted
from injected rules; the summary contains typed enums and preferences only.
This is a source/contract audit with regression tests, not an agent benchmark.

## Failure classes

- P1 — Generated local files: `init::prepare_and_run` wrote configuration and
  guidance without Git exclusion. A prose-only instruction cannot enforce this.
- P2 — Workflow ambiguity: the old skill joined pre-edit Issue selection and
  PR aggregation, but `pr::execute` requires pushed changes and creates a draft.
  Project guidance omitted installed-contract discovery and exit semantics.
- P3 — Ownership and index limits: Git ignores cannot suppress tracked-file
  changes or individual generated hunks in manually maintained files.
- P4 — Upgrade evidence: `migrate::execute` rendered guidance without the receipt
  used by `guidance::changes`; a later runtime template could reject pristine
  migrated guidance as an edit.

## Changes and falsifiable predictions

### chg-1 — Local exclusions

Evidence/root cause: P1; no Git-local exclusion asset existed in the init plan.
Fix/component: one transaction-managed local exclude block in the asset layer,
using Git's actual path, also included in migration preview and rollback.
Prediction: repeated init produces byte-identical exclusions; real worktree
`git check-ignore` succeeds. Risk: linked worktrees share the common exclude
file. Existing user rules remain intact; no broad directory rule is introduced.

### chg-2 — Native workflow and evidence

Evidence/root cause: P2; the skill's sequence did not distinguish the pre-edit
Issue checkpoint from the post-push PR operation. Exit 0 alone was ambiguous.
Fix/component: project entry and workflow skill now state Issue selection →
implementation/authorized commit and push → draft PR → ready → native observation.
They distinguish operation success, checks, intended merge and all Issue closure;
the skill covers exact-ID recovery after uncertain writes and existing authority.
Prediction: each described operation matches help/schema and executable behavior.
Risk: added text is justified by these gaps, but compliance by every Agent is not
proven by string assertions. The installed skill remains the detailed contract.

### chg-3 — Preserve manual content

Evidence/root cause: P3; ignoring a mixed AGENTS file would hide user work, while
an ignore rule cannot untrack an indexed file.
Fix/component: report `already_tracked` and `mixed_guidance_paths`; keep generated
assets and generated hunks out of commits, with explicit authorized untracking
of whole generated files. Document the limit in the skill and installation guide.
Prediction: generated-only files are ignored, manual guidance remains visible,
and init never mutates the index. Repository `.specgit.yaml` is untracked while
the local copy remains available; clean CI no longer requires that local file.

### chg-4 — Upgrade ownership

Evidence/root cause: P4; migration omitted the generator receipt.
Fix/component: migration records block hashes in its transaction. Exact pristine
2.0.0 templates have a narrow compatibility recognizer; edited blocks conflict.
The old renderer is ownership evidence only, never a newly injected prompt.
Prediction: both language fixtures upgrade without a receipt, deliberate edits
are rejected, and rollback removes the newly written migration receipt.

## Unchanged components and verification

Global host entry blocks already point to the installed skill and delimit ownership.
Setup refresh uses receipts and replaces exact owned blocks; uninstall preserves
user content. Hook context supplies observations and grants no mutation authority;
registration is not delivery, and transport acknowledgment is not human reading.
Hook completion text now names the intended target and every selected Issue closed,
matching the project and skill contract. Existing framing is preserved; no second
project block is injected.

source lint/tests, installed-runtime qualification and current-head three-platform
CI. Review actual rendered English/Chinese and registered-host outputs. If a
prediction fails, fix or revert the corresponding component change instead of
adding stronger repeated prose. Platform merge/closure and signed release
publication remain separate evidence checks.
