# GitLab 19.2 evidence ledger

Committed evidence ledger for GitLab support ([policy and roadmap](../gitlab-support.md)).
Every GitLab/glab behavioral claim that SpecGit will rely on is pinned here
**before** code: review rejects unanchored claims. Bound issues: #93–#100.

**Structure rules**

1. Columns: `# · claim · official anchor (URL) · version/tag/commit · CE applicability · read-only probe · confidence · status`.
2. Authority whitelist: **docs.gitlab.com**, **gitlab-org/gitlab**, **gitlab-org/cli** — at pinned tags. Versioned `glab … --help` output is supporting evidence only. Nothing else anchors a claim.
3. Status vocabulary: `✅ pinned` (citable) · `⏳ pending <owner>` · `⬇️ BLOCKED-live-cell` (live cell attempted, isolation contract or environment prevented the answer) · `UNKNOWN` (missing evidence ⇒ that path is **blocked**, never an inferred capability).
4. Version comparison trap: `metadata.version` carries a channel suffix (`19.2.4-ee`; CE reports bare `19.2.4`). The suffix (`-ee`/`-ce`/`-pre`) is a release-channel marker, **not** semver pre-release semantics — naive ordering ranks `19.2.4-ee < 19.2.4`. Rule: strip the suffix, compare the `x.y.z` triple. Raw-string semver comparison is forbidden.
5. Support range (self-managed, CE/Free tier): **>= 19.2.4 < 19.3.0**, fail-closed outside (planned diagnostic `gitlab_version_unsupported`, exit 3). Range/floor changes happen only via rebaseline deliveries. GitLab.com (SaaS) is judged by capability probing, never version pinning (#93).
6. Live-instance cells below were probed on `git.ycgame.com` = **19.2.4 CE** (`enterprise:false`, revision `06e8d813296`, authenticated `glab api /metadata`) — inside the supported range — using **glab 1.113.0** pinned to gitlab-org/cli tag `v1.113.0` (commit `d6288130`, tagged 2026-08-11; local build reports the same commit). Recorded payload fixtures: [`test/specgit-e2e/fixtures/gitlab/`](../../test/specgit-e2e/fixtures/gitlab/README.md).
